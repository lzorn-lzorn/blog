# 着色器
在真实的引擎中, 并不会让使用者自己手写大量着色器, 而是引擎会有大量提前写好的着色器和着色器模版. 所以将使用者写的 Shader 和引擎提供的 Shader 组合起来, 是现代引擎需要提供的功能.

## Uber Shader(Shader Template)
所谓着色器模版, 本质上一个字符串匹配和替换. 例如 引擎内置一个模板文件 `MaterialTemplate.hlsl`, 内置了占位符 `%USER_MATERIAL_STRUCT%` 和 `%USER_MATERIAL_CODE%`
```cpp
// MaterialTemplate.hlsl —— 引擎提供的 Uber Shader 骨架

// ===== 引擎公共部分 =====
struct VSOutput {
    float4 position : SV_Position;
    float3 worldPos : TEXCOORD0;
    float3 normal   : TEXCOORD1;
    float2 uv       : TEXCOORD2;
    float4 tangent  : TEXCOORD3;
};

struct GBufferOutput {
    float4 albedo   : SV_Target0;  // rgb: baseColor, a: metallic
    float4 normal   : SV_Target1;  // rgb: worldNormal, a: roughness
    float4 position : SV_Target2;  // xyz: worldPos
};

// ===== 用户逻辑占位符 =====
// %USER_MATERIAL_STRUCT%  —— 用户自定义的 uniform / 纹理声明
// %USER_MATERIAL_CODE%    —— 用户自定义的材质计算函数

// ===== 引擎提供的 G-Buffer 打包函数 =====
GBufferOutput PackGBuffer(
    float3 worldPos,
    float3 worldNormal,
    float3 baseColor,
    float  metallic,
    float  roughness)
{
    GBufferOutput o;
    o.albedo   = float4(baseColor, metallic);
    o.normal   = float4(worldNormal, roughness);
    o.position = float4(worldPos, 1.0);
    return o;
}

// ===== 像素着色器入口 =====
GBufferOutput MainPS(VSOutput input)
{
    // 1. 调用用户逻辑, 获取材质属性
    MaterialAttributes attr = EvaluateMaterial(input);

    // 2. 引擎统一处理 G-Buffer 打包
    return PackGBuffer(
        input.worldPos,
        normalize(attr.normal),
        attr.baseColor,
        attr.metallic,
        attr.roughness);
}
```
使用者使用某种方式, 例如 UE 的材质节点, 或者直接使用 Json 等格式, 翻译器将其转化为 HLSL 代码.
以json为例:
```json
{
  "name": "BrickWall",
  "parameters": {
    "baseColorTexture": "brick_albedo.png",
    "normalTexture": "brick_normal.png",
    "roughnessValue": 0.8
  },
  "logic": {
    "baseColor": "sample(baseColorTexture, uv).rgb * float3(1.0, 0.8, 0.6)",
    "normal":    "perturbNormal(sample(normalTexture, uv).rgb, tangent, normal)",
    "roughness": "roughnessValue",
    "metallic":  "0.0"
  }
}
```
解析并翻译为两段 hlsl, 
转义 uniform 声明, 并写入 `%USER_MATERIAL_STRUCT%`
```cpp
Texture2D baseColorTexture : register(t0);
Texture2D normalTexture    : register(t1);
SamplerState linearSampler : register(s0);

struct MaterialAttributes {
    float3 baseColor;
    float3 normal;
    float  roughness;
    float  metallic;
};
```

转义材质函数, 并写入 `%USER_MATERIAL_CODE%`
```cpp
MaterialAttributes EvaluateMaterial(VSOutput input)
{
    MaterialAttributes attr;
    float2 uv = input.uv;

    attr.baseColor = sample(baseColorTexture, uv).rgb * float3(1.0, 0.8, 0.6);
    attr.normal    = perturbNormal(sample(normalTexture, uv).rgb, input.tangent, input.normal);
    attr.roughness = 0.8;
    attr.metallic  = 0.0;

    return attr;
}
```
所以其本质就是字符串解析替换引擎.

## 编译特化
对于不用材质需要的不同功能, 例如某些材质需要遮罩, 另外的不需要, 以json为例
```json
{
  "features": { "masked": true, "twoSided": false }
}
```
翻译器生成不同的宏定义, 并在引擎填充文件的时候插入宏定义
```cpp
#define MATERIAL_MASKED 1
#define MATERIAL_TWOSIDED 0

// 使用 #if 控制
#if MATERIAL_MASKED
    if (attr.baseColor.a < 0.5) discard;
#endif
```
但是实际上不需要使用宏来控制, 只需要把所有宏的排列组合, 然后给每一种可能以 lazy + cache 的方式生成不同的 Shader 即可. 即 Shader 变体.
```cpp
class ShaderCache {
    std::unordered_map<uint64_t, ShaderBlob> cache;

    ShaderBlob* getOrCompile(const ShaderMacros& macros, const std::string& materialCode) {
        uint64_t key = hash(macros) ^ hash(materialCode);
        auto it = cache.find(key);
        if (it != cache.end()) return &it->second;

        // 生成完整源文件
        std::string source = loadTemplate("MaterialTemplate.hlsl");
        source = replace(source, "%USER_MATERIAL_STRUCT%", generateStruct(materialCode));
        source = replace(source, "%USER_MATERIAL_CODE%",   generateFunc(materialCode));
        source = prependMacros(source, macros);

        // 编译
        ShaderBlob blob = compileHLSL(source, "MainPS", "ps_5_0");
        cache[key] = blob;
        return &cache[key];
    }
};
```
这里有两种方案:
1. 首先翻译器会先生成带有一堆 #if 的Shader源码, 然后在编译的时候, 根据这些宏不同的组合编译为不同的Shader变体. (这里的宏作为字符串可以直接存在C++中).
2. 在生成 Shader源码的时候就直接生成不同的 Shader 源码, 而不是生成一个大文件再做分支.

这两种方案都是可以的
## 光照着色器
在 UE 中光照部分是由引擎定义的, 所以这里的着色器代码完全使用引擎的开发者提前写好的着色器. 例如 Lambert 漫反射的光照模型
```cpp
// DeferredLight.hlsl —— 引擎全局光照着色器

Texture2D<float4> gAlbedo   : register(t0);
Texture2D<float4> gNormal   : register(t1);
Texture2D<float4> gPosition : register(t2);

struct Light {
    float3 position;
    float3 color;
    float  radius;
    float  intensity;
};

StructuredBuffer<Light> lights : register(t3);

float4 MainPS(float4 screenPos : SV_Position, float2 uv : TEXCOORD0) : SV_Target
{
    // 从 G-Buffer 读取材质属性
    float4 albedoData   = gAlbedo.Sample(linearSampler, uv);
    float4 normalData   = gNormal.Sample(linearSampler, uv);
    float4 positionData = gPosition.Sample(linearSampler, uv);

    float3 albedo    = albedoData.rgb;
    float  metallic  = albedoData.a;
    float3 N         = normalize(normalData.rgb);
    float  roughness = normalData.a;
    float3 worldPos  = positionData.xyz;

    // 逐光源累积
    float3 result = 0;
    for (uint i = 0; i < lightCount; ++i) {
        float3 L = lights[i].position - worldPos;
        float  dist = length(L);
        L /= dist;

        float NdotL = saturate(dot(N, L));
        float attenuation = saturate(1.0 - dist / lights[i].radius);
        attenuation *= attenuation;

        // 简化 Lambert 漫反射
        float3 diffuse = albedo * NdotL * attenuation * lights[i].color * lights[i].intensity;
        result += diffuse;
    }

    return float4(result, 1.0);
}
```

# 材质系统的实现
对于材质系统的设计而言, 我们应该分清楚编辑器和运行时分别承担的功能. 对于材质模版, 已经引擎预先设置好的 Shader 基本属于编辑器的功能.

引擎编辑器负责将 Shader 从具体的 glsl 或者 hlsl 编译至中间表示的二进制字节码. 游戏运行时负责将二进制字节码实际编译为其 GPU 上实际运行的二进制.

> [!note] 热更新
> 对于热更新而言, 一般客户端启动时检测到版本不一致需要热更新时, 会像服务器请求下发新的资源. 此时客户端会告知服务器自己使用的图形 API, 然后会对应下发已经编译好的对应图形API的字节码.
> 对于 steam 这种平台而言, 其提供了更为灵活的内容分发单元Depot, 开发者只要将对应的字节码打包进 Depot 中, 当玩家安装DLC时, Steam 会自动下发. 甚至 Steam 可以自动托管 Shader 源码, 帮开发者自动编译原始的 shader 源码文件.
