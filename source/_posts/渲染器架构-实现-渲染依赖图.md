# 渲染编排
Render Dependency Graph 本质上是一个 Render Pass 的组合器, 外部通过 `addRenderPass`
的方式向内部添加 Pass, 最后通过 `Execute` 生成 `RHIRenderPass` 传给 RHI.

其内部的实现需要满足:
1. 本身进一步封装 RHI 的实现, 提供能被 RDG 识别和管理的 GPU 资源.
2. 内部通过 `addRenderPass` 添加 Pass 节点. 然后通过拓扑排序(Kahn算法)构建 DAG 图
3. 基于 DAG 图进行别名分析优化
4. 进行 Pass 合并和屏障生成
5. 在 RDG 中再次封装 `RHIResource` 为 `RDGResource`, 以支持外部 insight 调试
6. 瞬态内存分配器(Transient Resource Allocator) 来分配 RHI Resource Descriptor

# RDG 完整流程: Build -> Compile -> Execute

RDG 的一次完整执行分为三个阶段: Build(构建), Compile(编译), Execute(执行)。
其中 Build 和 Compile 是纯 CPU 侧的"声明 + 分析"过程, 不产生任何 GPU 命令; 真正的 GPU 命令提交发生在 Execute 阶段。

## Build 阶段(声明依赖)

Build 阶段通过 `RDGBuilder` 把"要做什么"声明出来, 只是记录, 不做任何渲染:

1. 创建资源:
   - `CreateTexture` / `CreateBuffer` 创建 RDG 资源(瞬态资源, 此时并不分配物理显存, 只拿到一个 `FRDGTexture*` / `FRDGBuffer*` 句柄)
   - `RegisterExternalTexture` / `RegisterExternalBuffer` 把外部已存在的资源注册进 RDG(导出资源, 生命周期跨越一帧, 不参与瞬态分配)
2. 添加 Pass:
   - `AddPass` 添加一个渲染 Pass, 通过 `RDGPassParameters` 声明它读取哪些资源(SRV)与写入哪些资源(RTV/UAV)
   - Pass 的回调(lambda)在 Build 阶段不会被执行, 而是被记录下来, 等到 Execute 阶段才被调用
3. 提取资源:
   - `QueueTextureExtraction` 把需要跨帧保留的资源提取出来, 交给上层继续使用

Build 阶段结束时, RDG 内部记录了一张"有向无环图(DAG)"的声明: 节点是 Pass, 边是资源读写依赖。但此时 Pass 之间还没有确定的执行顺序, 也没有做任何内存分配与屏障。

## Compile 阶段(分析依赖)

Compile 阶段把 Build 声明的 DAG 变成一张拓扑有序, 资源已分配, 屏障已就位的可执行图, 典型步骤:

1. 拓扑排序: 根据资源读写依赖, 用 Kahn 算法对 Pass 做拓扑排序, 得到从 0 开始的 PassId 序列(即执行顺序, 见下文 [PassId] 说明)
2. 剔除死代码(Culling): 从最终输出(如 BackBuffer)反向遍历, 把没有被引用到的 Pass 及其资源整条链路裁剪掉, 避免执行无用的渲染工作
3. 生命周期分析: 扫描排序后的 Pass, 计算每个瞬态资源的存活区间 [FirstTimeRef, LastTimeRef]
4. 别名分析 + 瞬态分配: 让存活区间不重叠的瞬态资源复用同一块物理显存(即下文的"瞬态内存分配器")
5. 屏障生成: 在资源读写状态切换, 以及别名复用边界处自动插入资源屏障, 保证 GPU 数据正确性
6. (可选)Pass 合并: 把相邻, 无依赖且兼容的 Pass 合并, 减少状态切换

Compile 结束后, RDG 得到一张可执行图, 交给 Execute 阶段。

## Execute 阶段(提交 GPU 命令)

Execute 按 Compile 生成的顺序遍历 Pass, 逐个执行 Build 阶段记录的回调(lambda), 在其中把实际的 RHI 渲染命令提交到命令列表; 瞬态资源在第一次被使用时才真正创建(见下文内存映射表)。

> 对照本文章开头的描述: `addRenderPass` 属于 Build 阶段; `Execute` 属于 Execute 阶段; 而拓扑排序, 别名分析, 屏障生成, 瞬态分配这些都属于 Compile 阶段。

# 瞬态内存分配器 Transient Resource Allocator
在实际的一次渲染中, 会出现大量的临时对象(各种资源, 纹理, 缓冲区), 这些对象占据大量显存同时其存活时间非常短(多数资源仅一帧), 称之为瞬态资源. 如果对这些瞬态资源逐一分配显存, 则对于次时代场景来说, 可以瞬间打爆显存.
所以瞬态内存分配器的作用是通过分析所有临时资源的生命周期, 让多个资源在不同时间段共用同一段物理显存, 从而实现节约内存.

其内部的工作流大致为: 资源标记 -> 生命周期分析 -> 区间分配 -> 物理内存实例化
在 RDG 内部将纹理或缓冲区分为:
- 导出资源: 这类资源需要给 CPU 读取, 亦或是其生命周期跨越了一帧. 其不参与瞬态分配
- 瞬态资源: 分配瞬态资源需要通过 `RDGBuilder` 内部的 create 创建的资源, 且也没有被标记为
外部引用的资源. 此时 `RDGBuilder` 会将其标记为 `Transient`.

对于每一个瞬态资源, RDG 会为其建立一个引用该资源的 PassId 集合. 从而计算出存活区间`[FirstTimeRef, LastTimeRef]` 其中 FirstTimeRef 是第一个被引用的 PassId, LastTimeRef是最后一次被引用的 PassId. 所以只要两个瞬态资源的存活区间不重叠则可以共用同一块缓存.

  
> [PassId]
> 这里的 PassId 是对所有 addRenderPass 之后的节点进行拓扑排序生成的从 0 开始的唯一 Id
> 同时按照 PassId 从小到大排列好, 得到 PassIds 序列


计算区间: 对于每一个 PassIds 序列中的 Pass 检查其所有 Read 和 Write 资源
```cpp
for(int32_t PassId = 0; PassId < SortedPass.size(); ++PassId)
{
    const RDGPass* Pass = SortedPass[PassId];
    for(RDGResource* Resource : Pass->Reads)
    {
        if (Resource->IsTransient)
        {
            Resource->FirstTimeRef = std::min(Resource->FirstTimeRef, PassId);
            Resource->LastTimeRef = std::max(Resource->LastTimeRef, PassId);
        }
    }

    for(RDGResource* Resource : Pass->Writes)
    {
        if (Resource->IsTransient)
        {
            Resource->FirstTimeRef = std::min(Resource->FirstTimeRef, PassId);
            Resource->LastTimeRef = std::max(Resource->LastTimeRef, PassId);
        }
    }
}

```

Example:
- Pass 0: 写入 ShadowDepth
- Pass 1: 读取 ShadowDepth 写入 GBufferA
- Pass 2: 读取 GBufferA, 写入 SceneColor

处理 Pass 0 时:
- ShadowDepth 的存活区间为 [FirstTimeRef=0, LastTimeRef=0]

处理 Pass 1 时:
- ShadowDepth 的存活区间更新 [FirstTimeRef=0, LastTimeRef=1]
- GBufferA 的存活区间为 [FirstTimeRef=1, LastTimeRef=1]

处理 Pass 2 时:
- GBufferA 更新为 [FirstTimeRef=1, LastTimeRef=2]
- 若 SceneColor 是瞬态资源则其存活区间更新为 [FirstTimeRef=2, LastTimeRef=2] (但往往不是)

在得到这个存活区间之后, 瞬态内存分配器的工作环境则已经被准备好了

Example:
- A: [0, 2] 4MB
- B: [1, 4] 8MB
- C: [3, 4] 3MB

上述例子中, 所有 FirstTimeRef 是按序排好的
- T0: 分配A, 占用 0-4MB
- T1: 分配B, A 依旧存活, 此时额外分配B, 堆增长 [0, 4MB] -> [0, 4MB] + [4MB, 12MB]
- T2: A死亡, 释放 [0, 4MB]
- T3: 分配C, B 依旧存活, 此刻可以复用 [0, 4MB], 分配 [0, 3MB]
- T4: B, C死亡, 释放 [4MB, 12MB] 和 [0, 3MB]

此时峰值内存仅仅花费了 12MB 小于预期的 15MB
上述例子仅仅是一个简化的例子, 因为在实际分配过程中瞬态内存分配器内部实际上维护了若干个堆,
例如颜色纹理, 深度纹理, 缓冲区, UAV等.

- RenderTarget 堆: 用于颜色纹理
- DepthStencil 堆: 用于深度/模版纹理
- Buffer 堆: 顶点缓冲, 结构化缓冲等

其由于不同资源其要求的对齐也是不同的.

而由于最终的内存实际上是在 GPU 的显存上, 所以瞬态内存分配器最后输出其实是一张内存映射表:
[RDG资源, 堆索引, 偏移量] 在 RDG 执行 Execute() 时, 当某个瞬态资源被第一次使用时, 其会向 RHI 请求在堆的指定偏移处创建对应资源. 其依赖于现代 API 的内存别名机制.
- DX12: 使用 `CreatePlacedResource` 传入堆内存和指针
- Vulkan: 使用 `vkCreateImage` 之后通过 `vkBindImageMemory` 绑定到堆内存的偏移区域

最后为了防止GPU上的数据竞争: 旧的内存数据还在使用, 新的资源就开始写入的情况. RDG 需要通过显式资源屏障和生命周期同步来解决这个问题.在分配器决定的区间边界上, RDG 会自动插入一个 UAV 屏障或者别名屏障(DX12 Aliasing Barrier 或者 Vulkan 的内存屏障) 其保证在 LastTimeRef 之后的 RenderPass 开始使用新资源之前, 对所有旧资源的访问就必须结束.

# 关于计算着色器
在实际操作中, RDG 本身可以调度的不仅是图形管线, 还有计算管线. 现代渲染器往往需要先调度计算着色器将一些场景信息渲染至一张图集上, 然后再让图形管线依赖该图集. 这个操作本身也是在 RDG 的调度中.

例如在 UE 中, Lumen 的调度会依赖 SDF 的计算, 而 SDF 是依赖于计算着色器的计算. 相当于图形管线依赖了计算管线的资源. 

Compute Pass 的声明:
```cpp
void FDeferredShadingSceneRenderer::UpdateGlobalDistanceFieldVolume(
    FRDGBuilder& GraphBuilder,
    const FViewInfo& View,
    FRDGTextureRef GlobalSDFTexture)
{
    // 1. 创建输出资源（RDG 管理生命周期）
    FRDGBufferRef DirtyRegionBuffer = GraphBuilder.CreateBuffer(
        FRDGBufferDesc::CreateStructuredDesc(
            sizeof(FDirtyRegion), MaxRegions),
        TEXT("DirtyRegionBuffer"));

    // 2. 声明 Compute Pass
    FUpdateGlobalSDFCS::FParameters* Params =
        GraphBuilder.AllocParameters<FUpdateGlobalSDFCS::FParameters>();
    Params->GlobalSDF = GraphBuilder.CreateUAV(GlobalSDFTexture);
    Params->DirtyRegions = GraphBuilder.CreateSRV(DirtyRegionBuffer);
    Params->NumRegions = NumDirtyRegions;

    // 3. 只声明, 不执行
    GraphBuilder.AddPass(
        RDG_EVENT_NAME("UpdateGlobalSDF"),
        Params,
        ERDGPassFlags::Compute,   // ← 标记为 Compute Pass
        [Params](FRHICommandList& RHICmdList)
        {
            // 这个 Lambda 在 RDG Execute 阶段才执行
            FComputeShaderUtils::Dispatch(
                RHICmdList,
                FUpdateGlobalSDFCS::GetComputeShader(),
                *Params,
                ComputeGroupCount);
        });
}
```

Graphics Pass 的声明
```cpp
void FDeferredShadingSceneRenderer::RenderLumenCardCapture(
    FRDGBuilder& GraphBuilder,
    FViewInfo& View,
    FRDGTextureRef CardAtlasTexture)
{
    // 1. 创建渲染目标
    FRDGTextureRef CardCaptureRT = GraphBuilder.CreateTexture(
        FRDGTextureDesc::Create2D(
            AtlasSize, PF_FloatRGBA,
            FClearValueBinding::Black,
            TexCreate_RenderTargetable | TexCreate_ShaderResource),
        TEXT("CardCaptureRT"));

    // 2. 声明 Graphics Pass
    FRenderTargetBinding RenderTargets[] = {
        FRenderTargetBinding(CardCaptureRT, ERenderTargetLoadAction::EClear)
    };

    GraphBuilder.AddPass(
        RDG_EVENT_NAME("LumenCardCapture"),
        { },  // 输入
        { CardCaptureRT },  // 输出
        ERDGPassFlags::Raster,   // ← 标记为 Graphics Pass
        [&View, CardCaptureRT](FRHICommandList& RHICmdList)
        {
            // 这个 Lambda 在 RDG Execute 阶段才执行
            RHICmdList.SetRenderTargets({ CardCaptureRT->GetRHI() }, nullptr);
            for (const FMeshDrawCommand& Cmd : View.CardCaptureCommands)
            {
                RHICmdList.SetPipelineState(Cmd.PipelineState);
                ApplyShaderBindings(RHICmdList, Cmd.ShaderBindings);
                RHICmdList.DrawIndexed(Cmd.IndexCount, 1,
                    Cmd.IndexStart, Cmd.BaseVertex);
            }
        });
}
```

其在 Compile 阶段会推导依赖
```cpp
// ============================================================
// FRDGBuilder::Compile()
// 分析所有 Pass 的输入输出, 推导依赖关系
// ============================================================

void FRDGBuilder::Compile()
{
    // ---- 1. 为每个资源记录：谁写它、谁读它 ----
    // 例如 GlobalSDFTexture：
    //   写者：UpdateGlobalSDF (Compute)
    //   读者：TraceMeshSDFs (Compute), SampleGlobalSDF (Graphics)
    //         ↓
    //   推导出依赖：UpdateGlobalSDF → TraceMeshSDFs
    //              UpdateGlobalSDF → SampleGlobalSDF

    // ---- 2. 拓扑排序 ----
    TArray<FRDGPass*> SortedPasses = TopologicalSort(Passes);
    // 例如结果：
    //   [1] UpdateGlobalSDF        (Compute)
    //   [2] UpdateSurfaceCache     (Graphics)
    //   [3] UpdateVoxelLighting    (Compute)
    //   [4] TraceMeshSDFs          (Compute)
    //   [5] ScreenProbeGather      (Compute)
    //   [6] RenderDiffuseIndirect  (Graphics)

    // ---- 3. 插入资源屏障 ----
    InsertBarriers(SortedPasses);
    // 例如：
    //   UpdateGlobalSDF 写 GlobalSDF (UAV)
    //   TraceMeshSDFs 读 GlobalSDF (SRV)
    //     ↓
    //   在两者之间插入 Barrier:
    //     GlobalSDF: UAV → SRV
}
```

最后在执行录制时, 便会生成对应的命令
```cpp
// ============================================================
// FRDGBuilder::ExecutePasses()
// 按拓扑排序的结果, 依次录制每个 Pass 的命令
// ============================================================

void FRDGBuilder::ExecutePasses()
{
    // 注意：以下所有调用都是"录制", 不是"执行"
    // Compute 和 Graphics 命令被录制到同一个 RHICmdList

    for (FRDGPass* Pass : SortedPasses)
    {
        RHICmdList.BeginEvent(Pass->Name);

        // 执行 Pass 的 Lambda（这里才真正"录制"命令）
        Pass->ExecuteLambda(RHICmdList);
        // 例如：
        //   [1] UpdateGlobalSDF Lambda 执行：
        //       RHICmdList.Dispatch(ComputeShader, ...)
        //       → 录制一条 Dispatch 命令
        //
        //   [2] UpdateSurfaceCache Lambda 执行：
        //       RHICmdList.SetRenderTargets(...)
        //       RHICmdList.DrawIndexed(...)
        //       → 录制 DrawCall 命令
        //
        //   [3] UpdateVoxelLighting Lambda 执行：
        //       RHICmdList.Dispatch(ComputeShader, ...)
        //       → 录制另一条 Dispatch 命令

        RHICmdList.EndEvent();
    }

    // 最终, RHICmdList.Commands 里混着：
    //   [Dispatch(UpdateGlobalSDF)]
    //   [Barrier(GlobalSDF: UAV→SRV)]
    //   [SetRenderTargets(...)]
    //   [DrawIndexed(...)]
    //   [Barrier(CardAtlas: RTV→SRV)]
    //   [Dispatch(UpdateVoxelLighting)]
    //   ...
    // 它们按顺序被录制到同一个命令列表
}
```
