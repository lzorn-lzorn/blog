对于一个现代渲染器是一个 CPU 和 GPU 共同协作的过程. CPU 端往往需要保证将各种资源按照一定的规则传递给 GPU, 而在 GPU 端往往通过 Shader 来实现具体的算法和效果. 对于 CPU 端, 其主体往往分为三个层面: 业务侧面, 渲染侧面 和 GPU 侧面. 这里指代的渲染侧面和业务侧面, 可以理解为实际执行渲染的模块和执行游戏逻辑的模块.
业务层负责提交渲染意图, 渲染层用于和 GPU 进行实质交互. 对于三个侧面, 分别代表三个线程(有时渲染线程和RHI也可以是一个线程, 将其分开是UE的策略):
- 业务层面: 负责提交渲染意图, 这里的渲染意图可以有若干种具体的实现, 可以将其封装为一个 RenderRequest 对象, 内部存一个当前渲染请求的类型和一个由业务线程指定具体的回调函数(UE实际上就是这么实现的, 但是其没有封装 RenderRequest 对象). 这里需要注意线程同步的时候对共享对象的访问, 此时在渲染线程中会直接拷贝一份对象中重要信息来避免对共享对象的访问. 同时在一帧当中会有很多次渲染意图的提交, 但是本质上的都是数据的更新, 之后在本帧的最后业务线程(往往是摄像机组件)会提交一次真正的渲染请求.
- 渲染层面: 渲染线程在收到渲染请求时, 此时往往是业务线程的一帧的最后一个请求. 此时渲染线程开始基于所有更新的数据来录制提交给 RHI 线程的绘制命令. 这其中基本包括
    - 构建视图数据和计算每个视图的可见性
    - 构建 PSO 数据
    - 构建, 编译, 执行渲染依赖图. 渲染依赖图执行完之后就得到了已经录制好的渲染命令
- RHI层面: 在收到渲染线程提交的渲染命令之后, 通过动态派发走进对应的API分支, 然后解析渲染命令最后向 GPU 发送绘制调用.

对于上述的三个线程, 以下称之为 Game线程, 渲染线程 和 RHI线程.

对于 GPU 端, 这里特指基于光栅化渲染关系的渲染器, 开发者至少需要实现两种 Shader: Vertex Shader 和 Pixel Shader. 
Vertex Shader: 顶点着色器主要是的功能是处理顶点属性, 并将处理完之后的顶点属性传递给下一个阶段
Pixel Shader: 像素着色器往往位于光栅化之后, 是给每一个像素上色的着色器, 这里也是主要算法实现的地方.

对于像素着色器来说, 其本质是一个数学公式(矩阵运算)通过从CPU侧面传来的数据, 再辅以基于物理的公式实现基于物理的真实感渲染. 

# Game 线程
在Game线程中, 常见的需求有三种:

## 数据更新请求
在UE中, 场景中的容器 `Actor` 想持有某种能力必须携带某个 `Component`, 而对于渲染而言, 则是 `UPrimitiveComponent`. 该组件提供向渲染器提交请求的能力. 
不同的需要渲染的物体使用不同的 `UPrimitiveComponent` 的子类, 从而提交其对应格式的数据.
例如 Game Thread 一个 Tick 结束后，命令队列的样子
```
CommandQueue = [
    // ---- 状态更新命令（按发生顺序）----
    UpdateTransform(Actor1),        // Actor1 移动了
    UpdateTransform(Actor2),        // Actor2 移动了
    UpdateBoneMatrices(Char1),      // 角色骨骼动画更新
    UpdateMaterialParam(Mat1),      // 材质参数变化
    AddPrimitive(NewMesh),          // 新物体加入场景
    UpdateTransform(Actor3),        // Actor3 被物理推动
    UpdateParticleData(Niagara1),   // 粒子系统更新
    RemovePrimitive(OldMesh),       // 物体被销毁
    UpdateMorphTargets(Char1),      // 角色表情变化

    // ---- 渲染请求命令（最后一个）----
    RenderViewFamily(ViewFamily),   // ← 触发整帧渲染
];
```
这里的最后一个渲染请求同时还是一个同步点, 游戏线程会主动调用 `FrameEndSync::Sync();` 避免Game线程领先太多.
同时对于多个渲染请求的情况, 可以选择将其合并为一个请求. 对于多个视口的情况, 其提交的 ViewFamily 也是不同的也就是说通常情况下一个独立进程的游戏, 其只会有一个 ViewFamily. 

## 主屏幕渲染请求
在一帧中实际上会提交多种数据更新请求, 但是对于渲染线程而言不会因为每提交一次数据更新就重新渲染一次(对于延迟渲染流程而言), 而是在最后一次提交中主动发出实际的渲染命令.
虽然上述说的一直都是渲染命令, 但是在 UE 的实现中, 并没有一个 Enum 来定义若干中命令, 而是通过传入会在渲染线程中被调用的回调函数来实现的. 所谓"实际的渲染请求", 也只不过是在回调函数中调用具体渲染器的 Render 函数. 例如:
```cpp
ENQUEUE([ViewFamily, Scene = World->Scene](FRHICommandListImmediate& RHICmdList) {
    FSceneRenderer* Renderer =
        FSceneRenderer::CreateSceneRenderer(&ViewFamily, Scene);
    Renderer->Render(RHICmdList);
    delete Renderer;
});
```
[注]: `GameViewportClient` 只是 View 的组织者, 因为渲染线程只需要使用 View 的数据, 而不需要对象(直接让渲染线程取对象会有线程的竞态问题), 所以会由 `GameViewportClient` 组织相机数据. 但是其数据来源依旧来自玩家当前相机的 View 数据

## 离屏渲染请求
在实际的游戏场景中, 往往会有各种画中画的场景, 例如: 狙击镜开镜, 小地图, 透光的且映照出内部场景的窗户等等. 面对这种情况, 现代渲染器可以会选择将这个场景单独渲染成一张 RenderTarget, 最后再将 RenderTarget 独立的渲染在屏幕中.
这里说的 RenderTarget 实际上是一种离屏渲染, GPU将图形绘制到一个独立的 Image 上, 然后再贴到屏幕上, 这种情况称这张图为 RenderTarget.
而且 RenderTarget 的渲染是独立于主屏幕的, 所以可以实现以上的画中画的效果. 在 UE 中该方式对应的 Component 为 `USceneCaptureComponent`, 其并不是 `UPrimitiveComponent` 的派生类, 而是独立的.
对于这种情况, 会有一个标志`bRenderInMainRender` 
 - true: 作为主渲染视口的一部分, 其会作为一个附加 Pass 在主渲染器的流程. 通过优先级执行谁先谁后.
 - false: 独立渲染窗口, 其会先绘制所有的 `USceneCaptureComponent` 请求的画面至一个离屏的 RenderTarget 上, 然后绘制主屏幕上的场景至 BackBuffer 中, 最后在绘制 UI 时使用 Image 控件对 Render Target 进行采样

# 渲染线程
在渲染线程这一侧, 我们主要讨论 Render() 被调用时具体发生了什么, 其更能体现出渲染侧面的整体架构. 在实际的渲光栅化染器设计中, 主要需要处理两个点:
1. 材质
2. 渲染通道

首先, 为了防止多线程下的数据竞争, 渲染线程会有一个场景, UI的镜像数据用于更新渲染.
之后对于 Render 有以下几个步骤:
```cpp
void FDeferredShadingSceneRenderer::Render(FRHICommandListImmediate& RHICmdList)
{
    FRDGBuilder GraphBuilder(RHICmdList);

    InitViews(GraphBuilder);
    /**
     * 1. Copy each View in ViewFamily base info to SceneView
     * 2. Create View Uniform Buffer
     * 3. Create GBuffer from RDGBuilder
     * 4. Create Depth Buffer (SceneDepth) from RDGBuilder
     * 5. Create Velocity Texture from RDGBuilder
     * 6. for each Light create Shadow View and Shadew Depth Texture
     */

    ComputeVisibility(GraphBuilder);
    /**
     * for each SceneView
     * 1. FrustmCull
     * 2. OcclustionCull
     * 3. GetViewRelevance
     * 4. Compute Shadow Visibility by Shadow View
     */

    FMeshElementCollector Collector(GraphBuilder, Scene, Views);

    GatherDynamicMeshElements(Collector);
    /**
     * for each RenderableElementProxy call virtual function GetDynamicMeshElements
     * 1. Select LOD depend on Distance, Screen Size, FOV
     * 2. Compute LOD Transition
     * 3. Get Material Proxy
     * 4. Create MeshBatch
     * 5. Submit MeshBatch to Collector   
     */
    Collector.ProcessTasks();

    ProcessPrePassMesh(Collector);
    ProcessBasePassMesh(Collector);
    ProcessShadowMesh(Collector);
    ProcessTranslucencyMesh(Collector);
    ProcessVelocityMesh(Collector);
    ProcessCustomDepthMesh(Collector);
    /**
     * ProcessCollectedMeshes: Mesh -> FMeshDrawCommand, which RHI Thread Handle
     * for each call process():
     * 1 MeshBatch.GetMaterialProxy() and filter out unnecessary Passes
     * 2 MeshBatch.VertexFactory.GetVertexShader(PassType)
     * 3 MaterialProxy.GetPixelShader()
     * 4 Create PSO (just example from UE, PSO State depend on your RHI Setting)
     *   - VertexShader 
     *   - PixelShader
     *   - VertexInput
     *   - PrimitiveType 
     *   - BlendState
     *   - DepthStencilState
     *   - RasterizerState
     *   - RenderTargets.xxx
     * 5 Get PSO State Cache by POS, Pipeline is giant Object. we must be create form Cache file or just one time by async
     * 6 Build MeshDrawCommand info
     *   - PSO
     *   - Shader Binding: Vertex Shader, Pixel Shader
     *   - Uniform Buffer (goto 7.)
     *   - Texture (goto 7.)
     *   - Geometry (goto 8)
     * 7 Build ShaderBindings with RDG
     *   1 MeshDrawCommand.ShaderBindings.AddUniformBuffer(RHI, MaterialProxy.GetMaterial().GetUniformBuffer)
     *   2 MeshDrawCommand.ShaderBindings.AddTexture(ResourceIndex, SamplerIndex, RHI)
     *   3 MeshDrawCommand.ShaderBindings.AddUniformBuffer(PrimitiveUniformBufferIndex)
     *   4 MeshDrawCommand.ShaderBindings.AddUniformBuffer(VertexFactoryUniformBufferIndex)
     *   5 MeshDrawCommand.ShaderBindings.AddUniformBuffer(ViewUniformBufferIndex)
     * 8. Build Geometry info
     *   - Vertex Buffer
     *   - Index Buffer
     *   - Index Count
     * 9 Add MeshDrawCommand to Collector
     */

    RenderPrePass(GraphBuilder);
    RenderLumenSceneUpdate(GraphBuilder);
    RenderBasePass(GraphBuilder);
    RenderShadowDepth(GraphBuilder);
    RenderLights(GraphBuilder);
    RenderTranslucency(GraphBuilder);
    RenderPostProcessing(GraphBuilder);
    // for each View AddPass and call CallIndexed, eg:
    /**
     *   void FDeferredShadingSceneRenderer::RenderBasePass(FRDGBuilder& GraphBuilder){
     *       for (FViewInfo& View : Views){
     *           const TArray<FMeshDrawCommand>& Commands = View.BasePassMeshDrawCommands;
     *   
     *           GraphBuilder.AddPass(
     *               RDG_EVENT_NAME("BasePass"),
     *               BasePassParameters,
     *              ERDGPassFlags::Raster,
     *               [&View, &Commands](FRHICommandList& RHICmdList){
     *                   RHICmdList.SetRenderTargets({ 
     *                       View.GBufferA->GetRHI(), View.GBufferB->GetRHI(),
     *                       View.GBufferC->GetRHI(), View.GBufferD->GetRHI() 
     *                   },
     *                   View.SceneDepth->GetRHI());
     *   
     *                   for (const FMeshDrawCommand& Cmd : Commands){
     *                       RHICmdList.SetPipelineState(Cmd.PipelineState);
     *                       ApplyShaderBindings(RHICmdList, Cmd.ShaderBindings);
     *                       RHICmdList.SetVertexBuffers(Cmd.VertexBuffers);
     *                       RHICmdList.SetIndexBuffer(Cmd.IndexBuffer);
     *                       RHICmdList.DrawIndexed(Cmd.IndexCount, 1, Cmd.IndexStart, Cmd.BaseVertex);
     *                  }
     *               });
     *       }
     *  
     */

    GraphBuilder.Execute();
    /**
     * 1. Compile() 
     *   - Pass elimination
     *   - Merging
     *   - Barrier insertion
     *   - Memory aliasing
     *   - Topological sort
     * 2. Execute()
     *   - Alloc GPU Resource form RHI, like RHICmdList.CreateTexture(Tex->Desc),
     *   - Execute the Lambda registered during AddPass execution
     * 3. Release Transient Resources
     */
  
    RHICmdList.EndFrame();
}
```

# RHI 线程
正如之前所言, RHI 单独开一个线程并不是必须的. 但是如果像 UE 一样选择开一个新的线程, RHI 线程的功能是将渲染线程录制的命令转义为 GPU 能识别的格式, 其核心是将各个平台的 API 的用统一种接口进行分发. 从而实现跨平台.
